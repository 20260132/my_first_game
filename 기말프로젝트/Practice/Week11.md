## AI 대화 기록
**Q1. 코드를 Thonny에서 쓴 후 pyinstaller을 깔고 .exe로 바꾼 상태인데 파일로드오류가 나. 이건 어떻게 해결해?**--> 
AI 답변 :
    코드상에 resource_path를 추가해서 "파일을 찾을 준비"는 마쳤지만, PyInstaller로 묶을 때 "이미지와 사운드 폴더도 같이 묶어줘!"라고 명령을 내리지 않아서 .exe 파일 안에 파일들이 빠진 채로 만들어졌기 때문.
    따라서 기존 코드가 들어있는 코드에 생성된 bulid 파일, .spec 파일을 삭제 해 깔끔하게 만들어준 후, Thonny에서 터미널을 연 후, 
    pyinstaller --noconsole --onefile --add-data "sprite;sprite" --add-data "sound;sound" main.py 이 코드를 넣어서 수정하면 됨. main은 본인 파이썬 이름을 넣으면 됨.
적용 결과 : 파일로드오류가 뜨지 않고 .exe 파일이 잘 열렸음.


**Q2. 파이썬 코드(.py)를 굳이 실행 파일(.exe)로 변환(빌드)하는 목적은 뭐야?** 
--> AI 답변 :
    게임을 플레이 할 사용자가 굳이 파이썬을 설치하지 않고 클릭만으로도 게임이 만들어지기 위함임. 또한 복잡한 소스 코드와 이미지, 사운드를 .exe 파일 하나로 깔끔하게 공유하거나 배포하기 쉽기 때문.

**Q3. 빌드된 .exe 파일을 실행했을 때 창이 켜지자마자 곧바로 튕기는 현상의 핵심 원인이 뭐야?**
--> AI 답변 : 
    .exe 파일은 실행되는 순간 보이지 않는 임시 폴더를 만들고 거기에 에셋을 풀은 뒤에 가동됨. 일반 상대 경로를 쓰게 되면 임시 폴더가 아닌 엉뚱한 곳에서 파일을 찾기 때문에 파일이 없다는 오류가 나서, 바로 꺼짐. 따라서 resource_path()를 적어주어 해결하면 됨. 이 함수는 게임이 파이썬 에디터에서 커졌는지, 임시 폴더에서 켜졌는 지 파악한 후 절대 경로를 찾아줌.


## resource_path() 를 써야 하는 이유
A. 문제 발생 원인 : 파이썬 환경이랑 다르게 .exe 파일 경우 실행 시 임시 폴더에 압축을 풀고 실행함. 기존 상대 경로를 쓰게 되면 파일을 찾지 못해 게임이 튕김.
B. 해결책 : 프로그램이 스스로 실행 환경을 인식해, 어떤 상황이든 정확한 파일을 찾도록 함.
